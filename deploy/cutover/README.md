# Пакет переключения боя Прагматики на v2

Красная зона: запускает владелец (шлюз G7) на `pragmatika-ru`. Подробный порядок действий и
живые проверки — в `CHECKLIST.md`. Здесь — состав и устройство.

## Состав

| Файл | Назначение |
|------|------------|
| `cutover.sh` | переключение: предусловия, бэкап, остановка прежнего стека, запуск v2, проверки |
| `rollback.sh` | откат на прежние образы (обратная миграция 026); `--restore-db` — из бэкапа |
| `lib.sh` | общие функции обоих скриптов |
| `verify-signatures.sh` | подпись всех образов `images.lock` (запускает владелец на Fornex) |
| `units-old-tree.sh` | только чтение: три юнита, которые ссылаются на старое дерево |
| `CHECKLIST.md` | чек-лист владельца: до, после, откат, срок хранения, заморозка |
| `expected-host-dirs.txt` | пути хоста боя по выводу владельца (сверка с боевым `.env`) |
| `images.lock`, `cosign.pub` | образы по digest, открытый ключ подписей |
| `schema-expected.sql`, `expected-pending.txt` | ожидаемая схема v2 и ожидающие миграции боя |
| `FREEZE_SRC` | коммит старого репозитория (заморозка G5) |
| `stack/deploy`, `stack/db` | compose, платформа 1.0.1, миграции с `rollback/026_down.sql` |

## Как это устроено

Имя проекта compose `pragmatika`, имена контейнеров, томов и сетей, а также `/etc/pragmatika`,
`/srv/pragmatika`, `/opt/pragmatika/local` остаются прежними. Новый стек разворачивается в
`/opt/pragmatika-v2/{deploy,db}`: compose, `images.lock`, боевой `.env` без снятых имён (600),
ссылка на `secrets.env`. Прежнее дерево `/opt/pragmatika` не меняется, прежние образы не удаляются.

Порядок `cutover.sh` (любой сбой после начала изменений ведёт к `rollback.sh`):

1. Предусловия, бой не меняется: подписи всех digest, целостность пакета, `FREEZE_SRC`, ресурсы,
   бой здоров (`/ready`, ботов 4), боевой `.env`, файлы app читаются его uid, тома боя пишутся
   uid app, сухой запуск `app --once`, `migrate --plan` на живой базе: ровно `app/026` и 45
   `applied-by-legacy`.
2. Бэкап: остановка записи (app, indexer), штатный `backup.sh --verify`, `pg_dump -Fc`, `.env` и
   `secrets.env`, архив `/opt/pragmatika` без `local/`, архив тома псевдонимизатора, список образов.
3. Остановка прежних контейнеров (образы и тома остаются).
4. v2: `postgres` → план → `migrate` → схема против ожидаемой → остальные сервисы по одному с
   проверкой health → `app` последним.
5. Проверки: `/ready`, боты, журнал, образы = `images.lock`, почта как до, метрики, выдержка.

Откат БД: миграция 026 переименовывает столбец и пересоздаёт функции поиска, старый код на ней
не работает. Поэтому `rollback.sh` применяет `db/app/rollback/026_down.sql` (одной транзакцией:
столбец и индекс назад, функции прежней редакции, записи `schema_migrations` v2 снимаются) до
старта прежних контейнеров. Данные, записанные после переключения, при этом сохраняются.
`--restore-db` — отдельная команда с предупреждением: возвращает БД и хранилище на момент до
переключения.

## Подписи образов

Если на боевом хосте есть `cosign` и в пакете `cosign.pub`, `cutover.sh` проверяет подписи сам.
Иначе обязателен `--signatures-verified signatures.txt` (вывод `verify-signatures.sh` с Fornex;
`cutover.sh` сверяет digest и sha256 `images.lock` с файлом). Молча пропустить проверку нельзя.

## Проверка пакета без боя

`tools/cutover.test.sh` — отказы и предохранители на заглушке docker;
`tools/cutover-synth.sh` — ход `cutover → rollback → cutover` на синтетическом бое (Fornex).
