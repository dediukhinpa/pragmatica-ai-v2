# Контракт POST /docx/amend (этап 8y)

Решение владельца 19.11.2026: номер сотрудника или поставщика принимается как есть; составной
номер («103/11-26 / 17/10») делается ПО ПРОСЬБЕ; «добавь к номеру» - допись, а не замена; замена
- только по явной просьбе «замени номер на ...». Без явной просьбы номер НЕ меняется (поведение
по умолчанию прежнее). Все новые поля запроса необязательны, ответ только дополнен: старый
клиент продолжает работать.

## Запрос

JSON-тело (или multipart: `file` + `params` с теми же полями, кроме `content_base64`):

| Поле | Тип | Смысл |
|------|-----|-------|
| `file_name` | string, обязателен | имя файла (для имени результата) |
| `content_base64` | string | docx, .doc или RTF (.doc и RTF конвертируются) |
| `own_requisites` | `{name, lines[]}` или нет | что вписываем в сторону `party` |
| `party` | `"customer"` (по умолчанию) \| `"executor"` | в чей блок вписываются реквизиты |
| `number_edit` | объект или нет | просьба поправить номер договора |

`number_edit`:

| Поле | Тип | Смысл |
|------|-----|-------|
| `mode` | `"append"` \| `"replace"` | допись к номеру или замена номера |
| `text` | string, 1-60 знаков | допись или новый номер; без переводов строк и управляющих символов |
| `separator` | string, до 10 знаков, необязателен | только для `append`, по умолчанию `" / "`; `""` допустим |

Нужен хотя бы один из `own_requisites` / `number_edit`, иначе 422 `nothing_to_do`. Можно только
правка номера (без `own_requisites`): блоки сторон тогда не читаются.

### party=customer (по умолчанию, как раньше)

Реквизиты вписываются в блок «Заказчик»/«Покупатель»: в заполнители и пустые строки, остаток -
абзацами под заголовком. Нет блока - 422 `customer_block_not_found`, блок уже заполнен - 422
`customer_block_filled`, остались поля без нашего значения - 422 `customer_placeholders_unfilled`.

### party=executor

Значения (`own_requisites` - реквизиты исполнителя/поставщика, присланные сотрудником)
вписываются в блок «Исполнитель»/«Поставщик»/«Подрядчик»/«Продавец» ТОЛЬКО в пустые места и
заполнители (пустые строки, «___», «ИНН ____»). Существующий текст не затирается никогда, поверх
заполненного блока ничего не добавляется:

- блок целиком пуст (заголовок, пустые строки, заполнители, подпись) - заполняется как у
  заказчика: наименование и строки под заголовком;
- в блоке есть готовый текст - вписываются только значения в поля с метками («ИНН ____»,
  «Р/с ____»); пустые строки внутри такого блока не заполняются; если в документе есть
  заполненный блок исполнителя, пустые блоки (подписи) не дополняются;
- нечего заполнять - `placeholders_filled` = 0, в `not_found` код `placeholders`, в `notes` нота;
- блока нет - не отказ: `not_found` = `party_block`;
- поля с меткой, для которых нет значения («Факс ____»), отказа не дают (в отличие от
  заказчика): считаются в `unfilled_placeholders` и описаны в `notes`.

Преамбула зеркальна: заполнитель имени перед «в лице»/«именуемое «Исполнитель»» (после «и»,
«с одной стороны», «между» или в начале абзаца) заменяется наименованием.

## Правка номера

Номер ищется среди первых 12 непустых абзацев: в абзаце, начинающемся со слова «Договор»/
«Контракт»/«Соглашение» (можно с «Проект»/«Типовой»), либо в абзаце из одного номера
(«№ 103/11-26»). Формы: «№ 103/11-26», «№103», «N 5», «No 5», без символа («Договор поставки
А-15 от ...»), номер в нескольких run, в простом поле. Ссылки в тексте («доверенность № 15»,
«к Договору № 5») не номер договора. Дата и год номером не считаются. Одинаковый номер,
повторённый в заголовке, правится везде одинаково.

- `append`: к номеру дописывается `separator + text`; повтор той же дописи не дублируется
  (`unchanged`). К прочерку («№ ______») дописать нельзя: `not_found`;
- `replace`: номер заменяется на `text` целиком (составной тоже); прочерк заполняется;
- правка идёт внутри существующего run (допись наследует форматирование последнего знака номера),
  абзац не пересобирается;
- несколько РАЗНЫХ номеров в заголовке - не правим, `ambiguous`; номера нет - `not_found`;
  остальное дополнение (реквизиты) выполняется как обычно;
- после правки код сверяет: запрошенная правка допустима, любая иная - 422 `verification_failed`.

Плохая просьба (неизвестный `mode`, пустой/длиннее 60 знаков `text`, перевод строки или
управляющий символ в `text`/`separator`, неизвестный `party`) - 422
`{"detail": {"error": "bad_request"}}`.

## Ответ 200

```json
{
  "file_name": "Договор.docx",
  "mime_type": "application/vnd.openxmlformats-officedocument.wordprocessingml.document",
  "content_base64": "...",
  "converted_from": null,
  "party": "customer",
  "preamble_filled": true,
  "customer_block_filled": true,
  "party_block_filled": true,
  "placeholders_filled": 3,
  "lines_added": 5,
  "unfilled_placeholders": 0,
  "not_found": ["signature_line"],
  "notes": ["В блоке «Заказчик» не найдена строка подписи: место подписи проверьте вручную."],
  "number_status": "appended",
  "number_before": "103/11-26",
  "number_after": "103/11-26 / 17/10"
}
```

| Поле | Когда | Смысл |
|------|-------|-------|
| `party` | всегда | сторона, в которую вписывали |
| `party_block_filled` | всегда | в блок стороны что-то вписано (для `customer` равно `customer_block_filled`) |
| `customer_block_filled` | всегда | `true` только при `party=customer` и успехе |
| `not_found` | всегда (может быть `[]`) | машинные коды ненайденного, см. ниже |
| `notes` | всегда | по каждому коду читаемая нота по-русски; плюс пояснения (остались поля, блок заполнен) |
| `number_status` | только если был `number_edit` | `unchanged` \| `appended` \| `replaced` \| `not_found` \| `ambiguous` |
| `number_before`, `number_after` | только если был `number_edit` | номер до и после (`null`, если не найден/неоднозначен); номер договора - не ПДн |

Без `number_edit` поля `number_*` в ответе ОТСУТСТВУЮТ: номер не тронут (клиент читает как
`unchanged`).

Коды `not_found`:

| Код | Что не найдено |
|-----|----------------|
| `preamble` | заполнитель наименования стороны в преамбуле (или он уже заполнен) |
| `party_block` | блок исполнителя (для `executor`; у заказчика это отказ 422) |
| `number` | номер договора: не найден или неоднозначен (различает `number_status`), либо на его месте прочерк при `append` |
| `signature_line` | в блоке стороны нет строки подписи (должность, «М.П.», «/ФИО/») |
| `placeholders` | `executor`: в блоке нет пустых мест, заполнять нечего, ничего не вписано |

Коды не повторяются. Пустой `not_found` - всё, что просили, найдено.

## Примеры

Допись к номеру и реквизиты заказчика:

```json
{"file_name": "Договор.docx", "content_base64": "...",
 "own_requisites": {"name": "ООО «Ромашка»", "lines": ["ООО «Ромашка»", "ИНН 7701001238 КПП 770101001"]},
 "number_edit": {"mode": "append", "text": "17/10"}}
```

Замена номера без реквизитов:

```json
{"file_name": "Договор.docx", "content_base64": "...",
 "number_edit": {"mode": "replace", "text": "Б-7/26"}}
```

Реквизиты исполнителя в пустые места:

```json
{"file_name": "Договор.docx", "content_base64": "...", "party": "executor",
 "own_requisites": {"name": "ООО «Тюльпан»", "lines": ["ООО «Тюльпан»", "ИНН 3333333333 КПП 444444444"]}}
```

Отказ: `422 {"detail": {"error": "bad_request"}}` (также `nothing_to_do`, `customer_block_not_found`,
`customer_block_filled`, `customer_placeholders_unfilled`, `verification_failed`,
`unsupported_format`); размер или время - 413; нет места на томе спула - 503.
